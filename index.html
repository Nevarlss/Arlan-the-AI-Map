1. Search: BFS, DFS, UCS, A*

Arlan studies the map of Kazakhstan: Astana, Karaganda, Balkhash, Almaty… which road should he take?

The idea

A search problem has four parts: states (cities), actions with costs (roads), a start (Astana) and a goal test (“is this Almaty?”). The answer is a plan: a list of actions. The computer builds a “what if” search tree, where every node is a whole path. The only real question is: which waiting path (the frontier) do we expand next?

AlgorithmExpandsData structureOptimal?
BFSshallowest nodequeue (FIFO)fewest steps
DFSdeepest nodestack (LIFO)no
UCSlowest g(n)priority queueyes (costs ≥ 0)
A*lowest g(n)+h(n)priority queueyes, if h is admissible

Why BFS can fail

A→B costs 2, B→F costs 10, A→C costs 8, C→F costs 1. Both routes take 2 steps, but cost 12 and 9. BFS counts steps, so it cannot tell them apart. UCS adds up costs, so it can.

A*: UCS with a compass

f(n) = g(n) + h(n): g is the cost already paid, h is a guess of the cost still to pay. A heuristic is admissible if it never overestimates: 0 ≤ h(n) ≤ h*(n). Then A* is optimal, because the best goal always looks cheaper than any wrong goal, so it is taken first. If h = 0, A* is exactly UCS. On grids, Manhattan distance is a typical h. A visited set stops endless loops in graphs with cycles.

heapq.heappush(pq, (g + h(nxt), g, nxt))   # A*: priority = f

Real use: Google Maps, game AI, robot navigation, network routing.

In plain words

Imagine searching a dark maze with a flashlight. BFS sweeps the light in widening rings, so the nearest places are checked first. DFS follows one corridor to its end, then backs up. UCS also watches the “fuel meter” (cost so far). A* adds a compass that points roughly toward Almaty, so it wastes less fuel on wrong turns. Trace on the code graph below: A→B (f=6) and A→C (f=7) are queued; B is expanded first, but later C→E→G wins with total cost 7, and A* returns it.

Try it in Python

import heapq
graph = {"A":[("B",1),("C",4)], "B":[("D",2),("E",5)], "C":[("E",1)],
         "D":[("G",5)], "E":[("G",2)], "G":[]}
h = {"A":6, "B":5, "C":3, "D":4, "E":2, "G":0}   # heuristic

def a_star(start, goal):
    pq = [(h[start], 0, start, [start])]          # (f, g, node, path)
    best = {start: 0}
    while pq:
        f, g, node, path = heapq.heappop(pq)      # smallest f first
        if node == goal:
            return g, path
        for nxt, cost in graph[node]:
            ng = g + cost
            if ng < best.get(nxt, float("inf")):  # found a cheaper way
                best[nxt] = ng
                heapq.heappush(pq, (ng + h[nxt], ng, nxt, path + [nxt]))

print(a_star("A", "G"))   # (7, ['A', 'C', 'E', 'G'])
Beyond the lecture: A* was published in 1968 by Hart, Nilsson and Raphael at Stanford Research Institute, to plan routes for the robot Shakey.

2. Local Search: when the path doesn’t matter

In Almaty, Arlan must place 8 charging stations so they don’t block each other. Nobody cares how he got there, only about the final layout.

The idea

Keep one (or a few) complete solutions and improve them with small steps. Memory use is tiny. You need three things: a state, its neighbors, and a score to maximize.

Hill climbing always moves to the best neighbor and stops when none is better. On the landscape [1,3,5,8,6,4,2] starting at 0 it reaches 8. Traps: a local maximum (a small hill), a plateau (flat area), a ridge.

How to escape the traps

  • Random restart: start many times and keep the best result.
  • Simulated annealing: accept a worse move with probability exp(ΔE/T). T cools down (T ← 0.95·T): explore first, refine later. Cooling too fast freezes a bad answer.
  • Local beam search: keep K states, then pick the best K successors of all of them.
  • Genetic algorithms: population → selection by fitness → crossover → mutation.
  • Gradient descent (continuous problems): x ← x − α∇f(x).

Classic problems: N-queens (score = number of conflicts) and the traveling salesman (neighbor = swap two cities).

In plain words

Imagine you are hiking in thick fog. You can only see the ground around your feet, so you keep stepping uphill. Sooner or later you stand on a small hill and every step goes down, even though a taller mountain exists elsewhere. Simulated annealing fixes this by sometimes allowing a step downhill. Early on (hot) it does this often and explores; later (cool) it almost never does, and settles on a peak.

Try it in Python

import math, random
land = [1, 3, 5, 8, 6, 4, 2, 5, 9, 7]      # height at each position

def anneal(x, T=3.0):
    while T > 0.01:
        y = max(0, min(len(land) - 1, x + random.choice([-1, 1])))
        dE = land[y] - land[x]
        if dE > 0 or random.random() < math.exp(dE / T):
            x = y                            # accept (sometimes even if worse)
        T *= 0.95                            # cool down
    return x

print(land[anneal(0)])                       # often 9, the global peak
Beyond the lecture: Simulated annealing comes from Kirkpatrick, Gelatt and Vecchi (Science, 1983), inspired by slowly cooling hot metal. Genetic algorithms were popularized by John Holland (1975).

3. Games: Minimax and Alpha–Beta

On the road Arlan meets a rival robot. Now the environment is a player too.

The idea

In a two-player zero-sum game, MAX wants a high score and MIN wants a low one. Each assumes the other plays perfectly. A leaf has its utility, a MAX node takes the max of its children, a MIN node takes the min.

Example: leaves (3, 12, 8), (2, 4, 6), (14, 5, 2). MIN picks 3, 2, 2. MAX picks the best of those: 3. The 14 never matters, because MIN would avoid that branch.

Faster: Alpha–Beta

Full search costs O(bm). Alpha–Beta tracks α (best guaranteed for MAX) and β (best guaranteed for MIN). If α ≥ β the remaining children can be skipped. The answer is the same as Minimax, only fewer nodes are visited, and good move ordering helps a lot.

Real games

Search to a limited depth and use an evaluation function Eval = w₁f₁ + … + wₙfₙ (pieces, position…). Danger: the horizon effect. If some moves are random (dice), use Expectimax: take the weighted average at chance nodes, e.g. ½·8 + ⅓·24 + ⅙·(−12) = 10.

In plain words

Think of chess. You imagine your move, then the best reply of your opponent, then your best answer, and so on. You pick the move whose worst case is the best. That is Minimax. Alpha–Beta adds a shortcut: once you see that a branch is already worse than something you have, you stop looking at it.

Try it in Python

def alphabeta(node, maximizing, alpha=-1e9, beta=1e9):
    if isinstance(node, int):                # a leaf holds its utility
        return node
    best = -1e9 if maximizing else 1e9
    for child in node:
        v = alphabeta(child, not maximizing, alpha, beta)
        if maximizing:
            best = max(best, v); alpha = max(alpha, best)
        else:
            best = min(best, v); beta = min(beta, best)
        if alpha >= beta:                    # prune the remaining children
            break
    return best

print(alphabeta([[3, 12, 8], [2, 4, 6], [14, 5, 2]], True))   # 3
Beyond the lecture: IBM’s Deep Blue beat world chess champion Garry Kasparov in 1997 using alpha–beta search at huge scale. AlphaGo (2016) beat Lee Sedol in Go by combining Monte Carlo tree search with neural networks.

4. Probability and Bayesian Networks

A smoke sensor in Karaganda goes off. Is it a fire, or just burnt tea?

The basics

Joint P(A,B), marginalization (sum out what you don’t need), conditional P(A|B) = P(A,B) / P(B). Example: P(High,Failure)=0.18 and P(Failure)=0.18+0.02=0.20, so P(Failure|High)=0.18/0.30=0.60. Bayes’ rule: P(F|A) = P(A|F)·P(F) / P(A).

Try it (default = lecture example: 5%, 90%, 10% → 32.14%).
Share of faulty machines: 5% Sensor sensitivity: 90% False alarm rate: 10% P(faulty | alarm) = 32.14 %

Why only 32%? Out of 1000 machines, 50 are faulty (45 alarms) and 950 are fine (95 false alarms). So 45 / 140. The base rate matters as much as sensor accuracy.

Bayesian networks

A directed acyclic graph with a probability table (CPT) per node: P(F,S,A) = P(F)·P(S|F)·P(A|S). For Fire→Smoke→Alarm: 0.02·0.90·0.95 = 0.0171. Inference by enumeration (smoke hidden): P(A|F)=0.856, P(A|¬F)=0.057, P(A)=0.07298, so P(F|A) = 23.46%. Variable elimination gives the same answer more cheaply. Sampling gives approximate answers: rejection (throws away ≈93% of samples), likelihood weighting (weights instead of rejection), Gibbs (MCMC). Explaining away: finding another cause (earthquake) lowers the belief in the first (burglary). A sparse network stores O(n·dk) numbers instead of O(dn).

In plain words

Imagine a medical test for a rare disease that is “90% accurate”. Most people are healthy, so even a small false-alarm rate produces many false positives. Out of everyone who tests positive, many are healthy. Bayes’ rule is simply the careful way of counting this: (true alarms) ÷ (true alarms + false alarms).

Try it in Python

def posterior(prior, sensitivity, false_alarm):
    true_alarms  = sensitivity * prior
    false_alarms = false_alarm * (1 - prior)
    return true_alarms / (true_alarms + false_alarms)

print(round(posterior(0.05, 0.90, 0.10), 4))   # 0.3214
Beyond the lecture: The rule comes from Thomas Bayes, published after his death in 1763. Judea Pearl introduced Bayesian networks in the 1980s (Probabilistic Reasoning in Intelligent Systems, 1988).

5. Hidden Markov Models

Arlan’s motor is getting hot. Is it Healthy, Degrading or Faulty? He can’t see it, only sensors.

The idea

An HMM has two chains: hidden states X that change over time (transition table T) and observations E that each state emits (emission table O), plus a start distribution π. Markov assumption: P(Xt+1 | Xt, …) = P(Xt+1 | Xt): tomorrow depends only on today. Careful: P(High|Faulty)=0.7 is not P(Faulty|High).

Four questions you can ask

  • Filtering (now?): predict → observe → normalize. belief ∝ O(e)·Σ belief·T
  • Prediction (future?): p·Tk, with no new readings.
  • Smoothing (past?): forward × backward messages use later evidence too.
  • Viterbi (best path?): like filtering but with max instead of sum, remembering the best predecessor.
Example. Start [0.8, 0.2], T=[[0.9,0.1],[0.2,0.8]], O(High)=[0.2, 0.7]. After the first High: [0.16, 0.14] / 0.30 = [53.3%, 46.7%]. Second High: predict [0.573, 0.427], correct [0.115, 0.299], normalize → [27.7%, 72.3%]. Faulty is now more likely.

Real use: predictive maintenance, speech recognition, robot localization.

In plain words

It is like guessing the weather outside a windowless room by watching whether visitors carry umbrellas. You never see the weather itself (the hidden state), only clues (the observations). After each new clue you do three steps: predict how the weather may have changed, weigh the clue, and rescale so the chances add up to 100%.

Try it in Python

import numpy as np
T = np.array([[.9, .1], [.2, .8]])        # transitions: Healthy, Faulty
O = {"High": np.array([.2, .7])}          # P(High | Healthy), P(High | Faulty)
belief = np.array([.8, .2])               # start belief

for t in range(2):                        # two "High" readings in a row
    if t > 0:
        belief = belief @ T               # 1. predict
    belief = belief * O["High"]           # 2. weigh by the evidence
    belief /= belief.sum()                # 3. normalize
    print(t + 1, belief.round(3))         # [0.533 0.467] then [0.277 0.723]
Beyond the lecture: The Viterbi algorithm (1967) was invented for decoding noisy signals. Rabiner’s 1989 tutorial made HMMs the standard tool in speech recognition.

6. MDP: decisions when moves are uncertain

The road is icy: “go forward” doesn’t always work. Arlan needs a rule for every situation.

The idea

A Markov Decision Process = states S, actions A, transition probabilities T(s,a,s′), rewards R and a discount γ. Lecture grid: reach G (+5), avoid X (−5), each step costs −0.1. A move works with probability 0.8 and slips left or right with 0.1 each; walls mean “stay”.

How to solve it

Q(s,a) = Σ T·[R + γV(s′)], V(s) = maxa Q(s,a), π(s) = argmaxa Q(s,a). Example: Q(H,UP) = 0.8·4.4 + 0.1·1.7 + 0.1·0.8 = 3.77.

Value iteration: start with V₀ = 0, compute Vk+1 only from the old Vk, stop when the biggest change is below 0.001 (15 iterations in the lecture example). The value of the goal “spreads” outward cell by cell. A high γ (0.9) cares about the future; a low γ (0.2) only about what’s close.

Key point: a policy is not a route. It tells you what to do in every state, because outcomes are random.

In plain words

Picture a robot on ice. Every cell has a number: “how good is it to stand here?” The goal cell is worth a lot, and that value flows backwards like water, so cells next to the goal become valuable, then their neighbors, and so on. Once every cell has a value, the best action is simply “step toward the neighbor with the best value”, allowing for the chance of slipping. The list of best actions is the policy.

Try it in Python

gamma = 0.9
# A tiny chain s0 -> s1 -> s2 (goal, reward +5).
# Each move succeeds with probability 0.8, otherwise the robot stays.
V = [0.0, 0.0, 5.0]
for _ in range(50):                        # value iteration
    V[1] = 0.8 * gamma * V[2] + 0.2 * gamma * V[1]
    V[0] = 0.8 * gamma * V[1] + 0.2 * gamma * V[0]
print([round(v, 2) for v in V])            # [3.85, 4.39, 5.0]
Beyond the lecture: The Bellman equation comes from Richard Bellman’s dynamic programming (1950s). Modern reinforcement learning, including game-playing agents, is built on MDPs.

7. Rational Decisions and Classical ML

The motor acts up. Keep driving, or stop for service?

Rational decisions

Rational means choosing well given what you knew before acting, not getting a lucky result. Rule: a* = argmax EU(a), with EU = Σ P(outcome|a)·U(outcome). Project A: 0.9·100 + 0.1·(−20) = 88. Project B: 0.6·200 + 0.4·(−50) = 100. The riskier B wins. Probability tells you what to believe, utility tells you what to do. Service threshold: act if p > cost_service / cost_failure = 2000 / 10000 = 20%.

Machine learning

Instead of writing rules, an algorithm learns ŷ = fθ(x) from data. Three families: supervised (labels), unsupervised (structure), reinforcement (rewards). Regression predicts a number (MSE, MAE, R²). Classification predicts a class or probability. Logistic regression: σ(z) = 1/(1+e−z), and the threshold τ is a policy choice, not a constant. A decision tree is easy to read but overfits; a random forest averages many trees.

Metrics: Recall = TP/(TP+FN), Precision = TP/(TP+FP). A model that always says “normal” has 98% accuracy when 2% of machines fail, but 0% recall. Risks: overfitting, data leakage, distribution shift, bad calibration.

In plain words

Probability tells you how likely a failure is. Utility tells you how much it hurts. A rational choice multiplies the two and compares the totals. A cheap check that prevents a rare but expensive failure is often worth it. A free action that risks a frequent small loss may not be. Learned models (ML) just supply the probabilities; the decision still needs the costs.

Try it in Python

def expected_utility(outcomes):            # list of (probability, utility)
    return sum(p * u for p, u in outcomes)

A = [(0.9, 100), (0.1, -20)]
B = [(0.6, 200), (0.4, -50)]
print(expected_utility(A), expected_utility(B))   # 88.0 100.0  -> choose B
Beyond the lecture: Expected utility theory was formalized by von Neumann and Morgenstern (1944). Random forests were introduced by Leo Breiman in 2001.

8. Unsupervised Learning: finding hidden structure

Arlan has logs from 50 sensors and not a single label. What is hiding inside?

  • K-Means: pick K centers → assign each point to the nearest → move centers to the mean → repeat. It minimizes inertia = Σ‖x−μ‖². Choose K with the elbow method, silhouette score and common sense (inertia always falls as K grows). Scale features first. Weak on odd shapes and outliers.
  • DBSCAN: a cluster is a dense region (eps, min_samples). Points are core, border or noise (−1). It finds crescents but struggles with mixed densities. Noise is not automatically a failure.
  • Curse of dimensionality: space grows exponentially (1010 cells in 10D), data becomes sparse and distances lose meaning.
  • PCA: finds axes of maximum variance (PC1, PC2 are orthogonal). PCA(n_components=0.95) keeps ≈95% of the variance. Trade-off: compact vs interpretable.
  • t-SNE / UMAP: non-linear maps for exploring data. Don’t read distances between islands literally.
  • Isolation Forest: anomalies are isolated by random splits in fewer steps (short path). An anomaly is a candidate for an expert to check, not a verdict.

Workflow: data → scale → PCA → clusters → validate → anomalies → expert.

In plain words

Imagine pouring a mixed bag of coins on a table. Nobody tells you which is which, yet you can still sort them by size and color. Unsupervised learning does the same with data: it finds groups (K-Means, DBSCAN), makes many measurements easier to see (PCA), and points at the odd coin (Isolation Forest). A human expert then decides what the groups mean.

Try it in Python

from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

# data: a table with one row per machine and one column per sensor
X = StandardScaler().fit_transform(data)       # put features on one scale
km = KMeans(n_clusters=3, n_init=10).fit(X)
print(km.labels_, km.inertia_)                 # cluster of each row, total cost
Beyond the lecture: K-Means goes back to Stuart Lloyd (1957, published 1982). DBSCAN was introduced in 1996 (Ester et al.), t-SNE in 2008 (van der Maaten and Hinton) and Isolation Forest in 2008 (Liu, Ting and Zhou).
